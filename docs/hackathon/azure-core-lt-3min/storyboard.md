to a bounded pilot and leadership decision.

## Editing rules

1. Use Athena as the only product name in the spoken and visible pitch.
2. Show architecture only after the working proof.
3. Keep the platform visual conceptual; do not expose subscriptions, internal endpoints, identities,
   or trust-anchor details.
4. Describe Epic as the proving ground, not the product boundary.
5. Do not claim production adoption, automatic remediation, or measured savings without evidence.

## Freeze fallback

If an in-development surface is not deployed by September 19:

- use the verified standalone presentation for the baseline-faulted-recovered lifecycle;
- use the packaged golden proof for the three environment profiles;
- show the explicit guidance-unavailable state rather than implying that verified guidance was
  rendered;
- retain the conceptual governance visual if Context Studio is unavailable; and
- present incident state, approved context, and correlation evidence as separate labelled surfaces,
  not as a fabricated single-screen experience.
